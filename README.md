# ops

GitOps for the self-hosted Services on nc8kg1101, a plain Linux Host. Every Stack is a Docker Compose project in this repo, and the repo is the only source of truth for what runs there.

Terms used here (Stack, Platform Stack, Service, Datastore, Deploy, Baseline, Tier, ...) are defined in [GLOSSARY.md](GLOSSARY.md). Design decisions are recorded in [docs/adr](docs/adr). Agents start at [AGENTS.md](AGENTS.md).

## Layout

| Path | Contents |
|---|---|
| `nc8kg1101/<stack>/compose.yaml` | One Stack per folder; the folder name is the Compose project name |
| `nc8kg1101/<stack>/<service>/service.yaml` | One Service plus the sidecars that exist only to serve it, listed in the Stack's `include:` |
| `nc8kg1101/<stack>/.sops.env` | SOPS-encrypted values for the Stack |
| `nc8kg1101/_baseline.yaml` | The Baseline every Service extends ([ADR 0006](docs/adr/0006-service-baseline-via-extends.md)) |
| `.doco-cd.nc8kg1101.yml` | nc8kg1101's doco-cd deploy config (see [Bootstrapping doco-cd](#bootstrapping-doco-cd)) |
| `scripts/bootstrap-nc8kg1101.sh` | The one-time bootstrap wizard for doco-cd and the ops Platform Stack |
| `scripts/monitoring-secrets.sh` | The wizard that sets the monitoring Stack's Page, Digest and Heartbeat credentials (see [Monitoring](#monitoring)) |
| `scripts/outline-oidc.sh` | The wizard that creates Outline's OIDC client at the IdP and stores its credentials |
| `host/` | What runs on nc8kg1101 outside Docker: the startup-order systemd unit and its pinned release (see [Startup order](#startup-order)) |
| `hosts.yaml` | The Hosts the shared Repo Tooling manages: only nc8kg1101 ([ADR 0012](docs/adr/0012-shared-repo-tooling.md)) |
| `nc8kg1101/monitoring/node-exporter/declared_containers.prom` | The declared containers and their Tiers, generated by `homelab-declared-containers` (see [Checks](#checks)) |
| `tools/host/` | Tests for `host/`: the unit passes `systemd-analyze verify`, Renovate reads the pin, and labels respect shared network namespaces |
| `tools/validate/` | This repo's `homelab-validate` arguments (`args`) and the wrapper that passes them |
| `.github/workflows/validate.yaml` | CI: the checks every PR must pass |
| `.env.example` | Keys for the gitignored repo-root `.env`: SSH access to each Host |
| `.sops.yaml` | Which age keys encrypt which files |

There is one Stack per app, each with its own Datastores ([ADR 0004](docs/adr/0004-stack-per-app-with-own-datastores.md)). Platform Stacks group Services by the role they play for the others:

| Platform Stack | Services |
|---|---|
| `edge` | Traefik, CrowdSec, nginx, mitmproxy (with its openresty sidecar) |
| `monitoring` | Prometheus, Alertmanager, Loki, Alloy, blackbox-exporter and their collectors and exporters |
| `ops` | doco-cd, stack-back (Backups), Apprise |

App Stacks are `authentik`, `outline`, `fuzzbin`, `ersatztv`, `dispatcharr`, `nzbhydra2` and `prowlarr`.

### Cutover in progress

nc8kg1101 still runs one umbrella group (`common`) in `nc8kg1101/common/docker-compose.yaml`, deployed by a Portainer agent. The groups were cut over to the layout above one PR per group:

1. doco-cd and the ops Platform Stack ([#300](https://github.com/asotbz/ops/issues/300))
2. edge ([#301](https://github.com/asotbz/ops/issues/301))
3. monitoring ([#302](https://github.com/asotbz/ops/issues/302))
4. asot into authentik and outline ([#303](https://github.com/asotbz/ops/issues/303))
5. xfer into one Stack per app ([#304](https://github.com/asotbz/ops/issues/304))

#300 moved stack-back out of `common` and Apprise out of `xfer` into `nc8kg1101/ops`. #301 moved Traefik, CrowdSec and nginx out of `common` and mitmproxy and openresty out of `xfer` into `nc8kg1101/edge`, which owns the `proxy` and `forward-proxy` networks ([ADR 0002](docs/adr/0002-role-based-networks-replace-whalewall.md)). Every Service Traefik routes to joins `proxy` whichever group it is in, and prowlarr and nzbhydra2 reach mitmproxy on `forward-proxy`; the groups kept `common_backend` among themselves until their own cutover. #302 moved the `monitoring` group into `nc8kg1101/monitoring`, which owns the `metrics` network, with Alloy in place of Promtail. #303 split the `asot` group into the `authentik` and `outline` Stacks, each with its own Postgres (moved by pg_dump/pg_restore); Outline keeps its Redis, Authentik no longer needs one, and Outline signs users in at the IdP. #304 split the `xfer` group into one Stack per app, each Library mounted by Role ([ADR 0008](docs/adr/0008-library-isolation-by-role.md)): Fuzzbin runs as the Music Videos Library's owner behind its gluetun sidecar, ErsatzTV reads every Library, and Dispatcharr reads ErsatzTV's channels through its public Client Path. Nothing joins `common_backend` any more but Apprise, which leaves it in its own PR. `common` now holds only the Portainer agent. Its container was started by hand, and nothing redeploys `common` any more. Each cutover applies the Baseline, the role-based networks and the volume naming rule, and removes the group from Portainer. The Portainer agent is then removed from the Host ([#305](https://github.com/asotbz/ops/issues/305)).

## How a Deploy works

Once doco-cd lands ([ADR 0001](docs/adr/0001-doco-cd-deploys-stacks.md)):

1. Open a PR. Declared state changes only this way.
2. Merge to `main`.
3. doco-cd, running on the Host in the ops Platform Stack, polls `main`. For every Stack that changed, it decrypts the Stack's SOPS files with the Host's age key and runs `docker compose up`.
4. Deploy results go to the Digest through Apprise.

doco-cd deploys only `nc8kg1101/<stack>/compose.yaml`. It never deploys or removes the legacy `docker-compose.yaml` groups, which Portainer or @jbruns still deploy until their cutover.

Deleting a Stack folder removes the Stack from the Host but keeps its data volumes, which are `external` ([ADR 0009](docs/adr/0009-volumes-named-for-their-stack.md)). Runtime actions on the Host, such as a forced recreate, go through `hops` from the shared Repo Tooling, never by editing the Host by hand.

## Startup order

Every Service has a `startup-order` label: 0 edge, 1 Datastores, monitoring core and anything a Service cannot
start without (such as gluetun, whose network namespace Fuzzbin joins), 2 Exposed Services, 3 sidecars, exporters
and the ops Platform Stack ([ADR 0003](docs/adr/0003-startup-order-via-systemd-unit.md)). `homelab-validate
compose` rejects a Service without one, and a test in `tools/host` fails when a Service whose network namespace
another joins is not at a lower level than the joiner. On the Host, label a container started by hand with
`docker run` `startup-order=skip` so startup-order leaves it alone.

The [startup-order](https://github.com/jbruns/homelab-components/tree/main/components/startup-order) Custom
Component acts on those labels across Stacks. A systemd unit, `startup-order.service`, ordered after
`docker.service`, runs its `stop` at shutdown and `start` at boot, with its state and logs in
`/var/lib/startup-order/`. doco-cd does not deploy it: the Host runs the release pinned in
`host/startup-order.pin`, which Renovate bumps without automerge. To install or upgrade it, check it, or roll it
back, follow [host/README.md](host/README.md#install-or-upgrade-startup-order).

## Monitoring

The monitoring Stack keeps this Host's telemetry on the Host ([ADR 0011](docs/adr/0011-host-keeps-its-own-telemetry.md)):

- Prometheus scrapes the exporters on `metrics`, and blackbox-exporter probes every Service with a `probe.url` label
  (`probe.module` picks the expected answer). A Service Protected by native OIDC also carries `probe.idp_url`, its
  login path, which must redirect to the IdP's authorize endpoint, and `probe.idp_auth: oidc`. Forward auth's first
  redirect goes to the outpost instead, so its Probe module comes with forward auth (#289).
- Alloy ships every container's logs, labelled by `stack`, `service` and `tier`, and Traefik's access log to Loki.
- Each alerting rule carries the Stack's `tier`. Alertmanager pages Pushover for `critical`, posts `critical` and
  `warning` to the Discord Digest grouped per Stack, drops `info`, and pings a healthchecks.io Heartbeat every
  minute from the always-firing `Watchdog`.

The notification credentials live in `nc8kg1101/monitoring/alertmanager/*.sops.txt`. Set or rotate them with
`scripts/monitoring-secrets.sh`, which opens a PR. `hops alerts`, `hops stop --for` (silences) and
`hops logs --loki` use this Stack.

## Secrets

- Every secret is SOPS-encrypted with age. `.sops.yaml` lists the recipients.
- Each Host has its own age key. nc8kg1101's private key lives only on the Host, for doco-cd, at `/etc/doco-cd/age.key` (root, 0600, in a 0700 directory), and offline with @jbruns. @jbruns holds a separate editing key. Files are moving from the old shared key to per-Host keys in [#298](https://github.com/asotbz/ops/issues/298).
- Edit a Stack's values with `sops nc8kg1101/<stack>/.sops.env`. Plaintext `*.env` files are gitignored; encrypted files are named `*.sops.*` and tracked.
- Never print a secret value; read SOPS files by key name only (see [AGENTS.md](AGENTS.md#secrets)).

## Bootstrapping doco-cd

doco-cd is bootstrapped once per Host by hand, then deploys itself from `main` ([ADR 0001](docs/adr/0001-doco-cd-deploys-stacks.md)). For nc8kg1101, run the wizard from a checkout of `main` on @jbruns' machine, after #300 merged:

```sh
scripts/bootstrap-nc8kg1101.sh
```

It needs the repo-root `.env`, the Host's private age key at `~/.config/sops/age/nc8kg1101.txt` (override with `AGE_KEY_FILE`) and sudo as `doogie@nc8kg1101.asot.bz` (override with `OPERATOR`). It asks before every change, and re-running it skips what is done. Its stages:

1. Check the tools, the checkout and SSH access.
2. Replace the placeholder notification URL in `nc8kg1101/ops/doco-cd/apprise_urls.sops.txt`, through a PR.
3. Install the Host age key at `/etc/doco-cd/age.key`, checked by hash and never printed.
4. Create the external volumes `ops_doco-cd_data` and `ops_stack-back_cache`, and the `metrics` network (owned by monitoring from #302).
5. Remove xfer's old `apprise` container once Portainer has redeployed xfer.
6. Copy `xfer_apprise_config` into `ops_apprise_config`. The old volume stays as the Rollback Volume ([ADR 0009](docs/adr/0009-volumes-named-for-their-stack.md)).
7. Redeploy `common` by hand from `~/ops`, which removes `common-backup` before the new stack-back starts. Avoid the 09:12 backup.
8. Run doco-cd once with `apply-self --bootstrap`. It deploys `nc8kg1101/ops`, including the long-lived doco-cd container, and exits.
9. Verify that doco-cd, stack-back and Apprise are healthy and stack-back's schedule is set. Also check that Apprise is reachable from `common_backend` and that no legacy container was touched.
10. Remove the old stack-back cache. The wizard then lists what to release a week later: the Rollback Volume and common's plaintext `stack-back.env`, both of which a rollback needs until then.

How doco-cd finds Stacks: its `POLL_CONFIG` polls `https://github.com/asotbz/ops.git` on `main` with `target: nc8kg1101`, so it reads only `.doco-cd.nc8kg1101.yml`. That file sets:

- `working_dir: nc8kg1101` and `compose_files: [compose.yaml]`, with auto-discovery at depth 1. Each `nc8kg1101/<stack>/compose.yaml` is a Stack. `nc4kg1201/` and the legacy `docker-compose.yaml` groups are never matched.
- `delete: true`, which removes only projects that doco-cd itself deployed and labelled. The Portainer and hand-deployed groups are never removed.

Another Host would get its own `.doco-cd.<host>.yml` and target. A cutover that adds `compose.yaml` to a legacy group folder hands that project to doco-cd on merge.

To rotate the Host key: add the new recipient in `.sops.yaml` and run `sops updatekeys` through a PR. Then replace `/etc/doco-cd/age.key` (wizard stage 3 with `AGE_KEY_FILE`) and `sudo docker restart doco-cd`.

If the bootstrap has to be rolled back:

1. `sudo docker rm -f doco-cd stack-back apprise`.
2. Revert #300 on `main`.
3. Redeploy xfer in Portainer, which brings back `apprise` on `xfer_apprise_config`.
4. Redeploy `common` by hand. It needs `~/ops/nc8kg1101/common/stack-back.env` again, from `sops -d nc8kg1101/common/stack-back.sops.env` (piped straight into the file, never printed).

## Shared Repo Tooling

`hops`, the Baseline validator, declared-containers, the CI workflows, the Renovate preset and agent-skills setup come from [jbruns/homelab-components](https://github.com/jbruns/homelab-components), pinned by tag or commit and bumped by Renovate. They read the Hosts from `hosts.yaml` and connection details from `.env` ([ADR 0012](docs/adr/0012-shared-repo-tooling.md)).

## Checks

Every PR and every push to `main` runs `.github/workflows/validate.yaml`. Its `validate` job passes only if every
other job did, and it is the one required check on `main`. The jobs call the reusable workflows from
homelab-components, pinned by commit:

| Job | What it checks |
|---|---|
| secrets, env, compose, cloudflare, isolation | `homelab-validate`: secrets are SOPS-encrypted, the Stack layout, every `${VAR}` is declared, each Stack renders and meets the Baseline, and a change to the ops Stack ships in its own PR |
| monitoring | `homelab-validate monitoring`: the monitoring Stack's configs, alerting and recording rules and their promtool tests in `tools/validate/rules` |
| declared containers | `declared_containers.prom` matches the Stacks |
| gitleaks | No secret in the PR's commits |
| renovate config, actionlint | `renovate.json` and the workflows |
| tool tests | `tools/`' own tests, including `tools/host`'s checks of the startup-order unit, its pin and the level of each shared network namespace |

Run them locally from the repo root. They need Python 3.11+, [uv](https://docs.astral.sh/uv/), Git and Docker with
the Compose plugin; none needs a key or Host access. Install the tools once, pinned:

```sh
uv tool install "git+https://github.com/jbruns/homelab-components@validate-v1.1.0#subdirectory=repo-tools/validate"
uv tool install "git+https://github.com/jbruns/homelab-components@declared-containers-v1.0.1#subdirectory=repo-tools/declared-containers"
```

Then:

```sh
tools/validate/homelab-validate             # every check (isolation compares with origin/main)
homelab-declared-containers --check         # or without --check, to regenerate declared_containers.prom
python3 -m pip install -r tools/requirements-test.txt && python3 -m pytest tools
```

`tools/validate/homelab-validate` runs `homelab-validate` with the arguments in `tools/validate/args`, one option
and its value per line, which CI passes too:

- `--legacy-stack NAME` for each legacy group of the [cutover](#cutover-in-progress). Its `docker-compose.yaml`
  files may stay, and inputs inside it (such as monitoring's configs) are skipped; every other rule still applies.
  The check fails once the group has a `compose.yaml` or is gone, so each cutover PR removes its line. The list
  only shrinks.
- `--path NAME=PATH` for each component `homelab-validate` reads, so a missing one fails instead of being skipped.
  edge added `traefik`; monitoring added `prometheus`, `rule-tests`, `alertmanager`, `loki`, `alloy` and `blackbox`.

`declared_containers.prom` is generated from the Stacks and committed; regenerate it whenever a Stack's Services
change. Prometheus reads it through node-exporter's textfile collector, mounted from the repo, and alerts when a
declared container is missing.
